# Pinned runtime dependencies for every Python service.
#
# Package manager: plain pip. Chosen over uv/poetry so a new contributor needs
# nothing but a Python 3.12 install, and so the Dockerfile has no extra
# bootstrap stage. `uv pip install -r requirements.txt` also works verbatim if
# you prefer uv locally -- see README.md.
#
# Pins are compatible-release (~=), and the number of components is the whole
# decision:
#
#   1.x and up   two components -- `pydantic~=2.9` allows >=2.9,<3.0. Patch and
#                minor updates are allowed, majors are not. Semver says minors
#                are compatible, and for these projects it holds.
#
#   0.x          THREE components -- `fastapi~=0.141.0` allows >=0.141.0,<0.142.0.
#                Below 1.0 there is no major to protect you: semver gives 0.x no
#                stability guarantee at all, so the MINOR is the breaking
#                position. A two-component `fastapi~=0.115` means <1.0, which is
#                every future 0.x release, forever -- and it was not theoretical:
#                that pin was written against 0.115 and silently resolved to
#                0.141.1, twenty-six minor versions of unreviewed change.
#
# So a 0.x pin names the minor series we actually test against, and moving it is
# a deliberate commit rather than a side effect of whenever an image last built.
# Regenerate a fully-locked set with `pip freeze` if the platform ever requires
# hash-pinned builds.
